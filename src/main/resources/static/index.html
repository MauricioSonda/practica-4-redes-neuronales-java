Prompt utilizado para iniciar el proyecto

Actúa como ingeniero de machine learning senior y desarrollador full-stack en Java. Necesito que me ayudes a completar una tarea universitaria de redes neuronales. Entrega código completo, funcional y listo para ejecutar, sin fragmentos incompletos ni "..." en el código.

## CONTEXTO DE LA TAREA
Debo implementar EN JAVA tres ejemplos de redes neuronales con datasets reales (comerciales o industriales) descargables de internet, con parámetros ajustados y resultados aceptables:

1. PATTERN RECOGNITION (clasificación): problema real de clasificación comercial o industrial.
2. FITTING (regresión): problema real de regresión comercial o industrial.
3. SERIES DE TIEMPO: problema de clasificación de series de tiempo, real o industrial.

Se permite usar frameworks (por ejemplo Deeplearning4j, Smile, Weka, Encog o implementación propia de MLP). Elige el que mejor funcione y justifícalo en una línea.

## DATASETS
- Propón para cada problema un dataset público real (UCI, Kaggle, UCR Time Series Archive, OpenML, etc.) con enlace directo de descarga.
- Prefiere datasets que se puedan descargar por URL directa desde el código (sin login) para que el programa funcione solo.
- Ejemplos de ideas (puedes proponer mejores): clasificación de fallas/calidad (Wine Quality, Steel Plates Faults, Bank Marketing), regresión (Concrete Compressive Strength, Energy Efficiency, Airfoil Self-Noise), series de tiempo (UCR: FordA, ECG200, Wafer, ItalyPowerDemand).
- Incluye el preprocesamiento necesario (normalización, codificación de etiquetas, split train/validation/test).

## REQUISITOS TÉCNICOS
- Lenguaje: Java 17+, proyecto con Maven (pom.xml completo con dependencias).
- Estructura de proyecto clara: un módulo/paquete por ejemplo (classification, regression, timeseries) más el módulo web.
- Hiperparámetros ajustados: muestra la configuración final (capas, neuronas, activación, learning rate, épocas, optimizador, regularización) y explica brevemente cómo los ajusté (prueba de varias configuraciones o validación cruzada).
- Métricas:
  - Clasificación: accuracy, precisión, recall, F1, matriz de confusión.
  - Regresión: RMSE, MAE, R², gráfica real vs predicho.
  - Series de tiempo: accuracy, F1, matriz de confusión, curva de pérdida.
- Resultados aceptables: si el primer intento da resultados pobres, itera con ajustes y dime cuáles hiciste.
- Fija semillas aleatorias para reproducibilidad.
- Código comentado en español.

## PÁGINA WEB PÚBLICA (ENTREGABLE FINAL)
Crea una aplicación web que permita ejecutar los 3 ejemplos y visualizar resultados:
- Backend en Java (Spring Boot o Javalin) que exponga endpoints para entrenar/ejecutar cada modelo y devolver métricas y datos de gráficas en JSON.
- Frontend con HTML/CSS/JS (puede usar Chart.js) con:
  - Una pestaña o sección por ejemplo (Clasificación, Regresión, Series de tiempo).
  - Botón "Entrenar / Ejecutar", indicador de carga y opción de modificar hiperparámetros clave (épocas, learning rate, neuronas).
  - Visualizaciones: curva de pérdida, matriz de confusión, real vs predicho, métricas en tarjetas.
  - Para evitar tiempos de espera largos en hosting gratuito, incluye modelos pre-entrenados o entrenamiento ligero con opción de cargar resultados guardados.
- ESTÉTICA MODO OSCURO CON CAFÉS OSCUROS Y CONTRASTE:
  - Fondo principal café muy oscuro (ej. #1a1210 / #211714).
  - Tarjetas y paneles en café oscuro medio (ej. #2b1d17 / #3a2820).
  - Acentos en tonos cálidos de alto contraste (caramelo #d69a5b, crema #f2e3d0, ámbar #e8a94d).
  - Texto principal crema claro sobre fondo oscuro, buen contraste (WCAG AA).
  - Gráficas con paleta cálida (caramelo, ámbar, terracota, crema) sobre fondo oscuro.
  - Diseño responsivo, tipografía limpia, bordes redondeados, sombras suaves.
- Debe estar listo para desplegarse públicamente: incluye Dockerfile y las instrucciones paso a paso para desplegar gratis en Render, Railway o Fly.io, y que el resultado sea un enlace público.

## ENTREGABLES QUE DEBES GENERARME
1. Árbol de carpetas del proyecto completo.
2. Todos los archivos con su código completo (pom.xml, clases Java, frontend, Dockerfile, .gitignore).
3. README.md con: descripción, requisitos, cómo correr cada ejemplo en local, cómo correr la web, cómo desplegar, enlaces a datasets.
4. Un resumen por ejemplo: dataset (con enlace), arquitectura de la red, hiperparámetros finales, métricas obtenidas y análisis breve de resultados.
5. Guía para subir el proyecto a GitHub (comandos git) y publicar un ejecutable público (GitHub Releases con el JAR y/o enlace de la web desplegada).
6. Lista de capturas de pantalla que debo tomar como evidencia para el reporte (qué pantalla, qué ejecutar).
7. Plantilla de la sección "Uso de IA generativa" del reporte, donde indique el origen (modelo usado) y espacio para pegar los prompts.

## REGLAS DE RESPUESTA
- Si la respuesta es muy larga, divídela en partes numeradas y avísame al final de cada parte qué sigue; espera mi "continúa" para la siguiente.
- No inventes resultados de métricas: si no puedes ejecutar el código, indícame qué valores aproximados esperar y dime que debo correrlo para confirmar.
- Verifica que las versiones de las librerías sean compatibles entre sí.
- Antes de escribir código, dame en 10 líneas máximo el plan: datasets elegidos, framework y arquitectura de cada red.
